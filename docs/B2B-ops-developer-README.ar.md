# تسليم المطوّر — B2B ops (Laravel 13 + Vue 3 + Tailwind 4)

هذه الحزمة فيها ملفان:

| الملف | الغرض |
|---|---|
| `B2B-ops.env` | ملف البيئة المحلي **الكامل بكل أسراره** كما يعمل عند سالم. انسخه إلى جذر المشروع باسم `.env` |
| هذا الملف | ما تحتاجه لتبدأ خلال دقائق |

> **تنبيه أمني**: الملف يحوي أسرارًا حقيقية (مفتاح التطبيق، سر JWT، كلمة مرور قاعدة البيانات، كلمة مرور الحسابات، رمز تتبع المركبات).
> لا ترفعه إلى GitHub ولا إلى أي مستودع أو مجموعة، ولا تنسخه خارج جهازك. احذف الرسالة من واتساب بعد حفظ الملف.

## 1. الوصول

- **المستودع**: <https://github.com/salem-cell/scm-ops-laravel> (خاص؛ تحتاج دعوة من سالم على حسابك في GitHub).
- **الفرع الرئيسي**: `main`. النسخة الحية: <https://scm-ops-laravel.vercel.app> (Vercel + قاعدة Neon PostgreSQL).
- **بيئة الإنتاج لها ملفها الخاص** في Vercel، وليست هذا الملف. الوصول إليها بدعوة من سالم عند الحاجة.

## 2. التشغيل لأول مرة

المتطلبات: PHP 8.3 (مع pdo_mysql, mbstring, openssl, intl, curl, fileinfo, zip, gd, sodium)، Composer 2، وDocker Desktop أو خادم MySQL 8. Node 20+ فقط عند تعديل الواجهة.

</div>

```bash
git clone https://github.com/salem-cell/scm-ops-laravel.git
cd scm-ops-laravel
# ضع B2B-ops.env هنا باسم .env ثم:
php tools/setup.php --docker
php artisan serve --port=8000
```

<div dir="rtl">

افتح <http://127.0.0.1:8000>. السكربت لا يغيّر أي قيمة موجودة في `.env`، فستعمل بنفس الأسرار وكلمة المرور التي في الملف.

- **قاعدة البيانات**: الملف مضبوط على MySQL محلي بالمنفذ `3307` (نسخة محمولة عند سالم). مع Docker غيّر `DB_PORT` إلى `3306` واترك السكربت يولّد كلمة مرور الحاوية، أو أبقِ القيم كما هي واستخدم MySQL الخاص بك بنفس الاسم والمستخدم وكلمة المرور.
- **الحسابات التجريبية**: `admin` (كل الصلاحيات) · `sales` · `wm` · `inv` · `proc` · `disp` · `worker` · `driver` · `gm` · `finance`. كلمة المرور لها جميعًا هي `SEED_PASSWORD` في الملف.
- **إعادة التحميل من الصفر**: `php tools/setup.php --fresh` (يمسح الجداول ويعيد البيانات التجريبية).

## 3. ما في ملف البيئة

| القيمة | ملاحظة |
|---|---|
| إعدادات التطبيق وقاعدة البيانات المحلية | نفس بيئة التطوير عند سالم |
| `APP_KEY`، `JWT_ACCESS_SECRET`، `SEED_PASSWORD`، `DB_PASSWORD` | قيم حقيقية؛ تعمل مباشرة |
| `MAPBOX_PUBLIC_TOKEN` | رمز عام (pk.) للخرائط في المتصفح |
| `WIALON_BASE_URL` و`WIALON_TOKEN` | مزوّد تتبع المركبات الحي؛ الرمز شخصي، لا يُشارك |
| بقية التكاملات (تخزين، واتساب، ERP، منصة المبيعات) | فارغة = النظام يعرض «بانتظار التكامل» بصدق ولا يرسل شيئًا |

## 5. اقرأ قبل أول تعديل

- `docs/TEAM-START.ar.md`: دليل الفريق الكامل بالعربية (خريطة المشروع، قواعد لا تُكسر، طريقة العمل على GitHub).
- `docs/CONVENTIONS.md` للخادم، و`docs/FRONTEND.md` للواجهة، و`docs/RUNBOOK.md` للتشغيل والنشر.
- `docs/finance/ARCHITECTURE.ar.md`: المحرك المحاسبي (قيد مزدوج، قواعد الترحيل، قرارات المدير المالي المعلّقة).
- `docs/integration/RUNBOOK.md`: طبقة التكامل مع منصة المبيعات.

## 6. قواعد ثابتة في هذا المشروع

1. **المخزون لا يتغير إلا عبر** `app/Services/Inventory/InventoryService.php`. لا كتابة مباشرة على جداول الأرصدة.
2. **الصلاحيات تُفرض في الخادم** (`perm:*` على المسارات)، والواجهة تخفي فقط.
3. **لا أسرار في المستودع** إطلاقًا، ولا في `.env.example`. ملف `.env` يبقى على جهازك فقط.
4. **القيود المحاسبية لا تُعدَّل ولا تُحذف**؛ التصحيح بقيد عكسي مرتبط بالأصل.
5. **ما لم يُدمج بعد يُعرض كـ «بانتظار التكامل»**، لا ببيانات وهمية.
6. **الاختبارات تمر على MySQL وPostgreSQL** قبل الدمج في `main`؛ أضف اختبارًا لكل سلوك جديد.
7. **هوية الواجهة واحدة**: المكوّنات المشتركة في `resources/js/components` وأنماط `resources/css/app.css`؛ لا أنماط مخصصة لصفحة بعينها.
