# 🚀 دليل النشر السريع والتحديث الدوري لمشروع SCM OPS

هذا الدليل يوضح الخطوات القياسية المعتمدة لتطوير، ورفع، وتحديث المشروع بأمان من جهازك المحلي إلى مستودع GitHub وسيرفر الإنتاج، مع إجراءات التحقق السريع.

---

## 🧭 دورة العمل المختصرة (Workflow Overview)

```text
[ جهازك المحلي ]               [ GitHub ]               [ سيرفر الإنتاج ]
git push origin main  ───►  EngYemen21/scm-ops-2  ───►  bash deploy.sh
```

---

## 💻 المرحلة 1: على جهازك المحلي (قبل الرفع)

بعد الانتهاء من أي تعديل برمجي أو إضافة ميزة جديدة:

### 1. التحقق من سلامة الكود والاختبارات محلياً:
```bash
php artisan test --compact
```
*(تأكد من اجتياز الاختبارات بنجاح لمنع رفع أي كسر برمجي إلى الإنتاج)*.

### 2. رفع التحديثات إلى GitHub:
```bash
git add .
git commit -m "وصف واضح للتحديث الجديد"
git push origin main
```

---

## 🖥️ المرحلة 2: على السيرفر الحي (تنفيذ التحديث)

ادخل إلى سيرفرك عبر الـ Terminal، وتوجه إلى مجلد المشروع:

```bash
cd ~/erp.systemtesting.net
```

ثم نفّذ **أمراً واحداً فقط**:

```bash
bash deploy.sh
```

### ⚙️ ماذا يفعل سكربت `deploy.sh` تلقائياً في ثوانٍ؟
1. 🛡️ **نسخة احتياطية فورية:** يأخذ Dump مضغوطاً لقاعدة البيانات في `storage/backups/`.
2. 🔒 **وضع الصيانة:** يفعّل الصيانة المؤقتة لتفادي أخطاء المستخدمين أثناء التحديث.
3. 📦 **سحب الكود:** يجلب آخر تحديثات GitHub المعتمدة عبر `git reset --hard origin/main`.
4. ⚙️ **تحديث المكتبات:** يشغّل `composer install --no-dev --optimize-autoloader`.
5. 🎨 **أصول الواجهة:** يفحص ويعتمد أحدث حزم `public/build`.
6. 🗄️ **قاعدة البيانات:** يطبّق أي جداول أو تعديلات جديدة عبر `php artisan migrate --force`.
7. 🔑 **الصلاحيات:** يزامن أي صلاحيات جديدة مع أدوار النظام عبر `scm:sync-permissions`.
8. ⚡ **تسريع الكاش:** يجدد الكاش بالكامل (`config`, `route`, `view`) ويعيد تشغيل الـ Workers.
9. 🔍 **فحص النزاهة:** يتحقق من تطابق المخزون والمالية (`scm:reconcile` و `scm:finance-check`).
10. 🔓 **إعادة التشغيل:** يلغي وضع الصيانة ويعيد الموقع للجمهور فوراً.
*(وفي حال حدوث أي خطأ، يقوم السكربت تلقائياً بعمل **Rollback** واسترجاع قاعدة البيانات فوراً)*.

---

## 🔍 المرحلة 3: التحقق والتأكد من عمل المشروع (Verification)

للتأكد من أن السيرفر يعمل بكامل كفاءته بعد التحديث:

### 1. فحص صحة واستجابة السيرفر (Health Check):
```bash
curl -I https://erp.systemtesting.net/up
```
*(يجب أن يظهر كود `HTTP/1.1 200 OK`)*.

### 2. فحص مجدول المهام التلقائي (Scheduler):
```bash
php artisan schedule:list
```
*(يجب أن تظهر مهام مزامنة الـ GPS والتكاملات بمواعيد تشغيلها القادمة)*.

### 3. الفحص الشامل الآلي لكافة الواجهات والتقارير (Smoke Test):
```bash
SMOKE_PASSWORD=Secret123! node tools/smoke.mjs https://erp.systemtesting.net admin
```
*(يختبر 114 نقطة اتصال وشاشة ويقيس سرعة السيرفر — المعيار: `0 failed`)*.

## 🚨 خطة الطوارئ والاسترجاع اليدوي (Manual Rollback)

إذا احتجت في أي وقت استرجاع قاعدة البيانات يدوياً إلى لحظة ما قبل التحديث:
1. تجد جميع النسخ الاحتياطية محفوظة في مسار:
   ```bash
   ls -lh storage/backups/
   ```
2. لاسترجاع أي نسخة محددة:
   ```bash
   gunzip < storage/backups/db_backup_YYYYMMDD_HHMMSS.sql.gz | mysql -u USER -p DATABASE_NAME
   php artisan config:cache
   ```
